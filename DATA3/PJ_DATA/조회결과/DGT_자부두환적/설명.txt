DGT 반출입 목록 기반 자부두 환적 명세 조회

실행 코드: 크롤링 코드/DGT/dgt_self_ts_job.py
기존 요청 함수: 같은 폴더의 dgt_spec_job.py를 읽어서 재사용합니다.
기존 실행·카카오·노트북 종료 함수는 호출하지 않습니다.
필요 환경: Python 3.10 이상, 표준 라이브러리, Windows. 기존 파이참 인터프리터 사용 가능.

1. 조회 대상
PJ_DATA/dgt.csv의 Class가 TI, TX, TL인 행을 먼저 추립니다.
T/S 구분 열에 값이 없더라도 Class의 환적 표시를 사용합니다.
번호를 정규화하고 중복을 제거합니다. 원본 환적 행의 시각은 대상 DB에 별도 보존합니다.
PJ_DATA/조회기록/DGT_명세_20261018/targets.json에 기록된 HJNC/BPT 번호 전체를 제외합니다.
성공 CSV에 포함되지 않은 오류·기간 불일치 번호도 이미 조회한 번호이므로 제외합니다.
2026-10-19 점검: 원본 919,084행/564,983번호, 환적 표시 174,165행/169,773번호.
기존 HJNC/BPT 번호 합집합 64,494개 제외. 이번 대상 105,279번호.
기존 DGT_remaining_130522.csv는 이번 대상의 기준으로 사용하지 않습니다.

2. 실행 방법: 파이참 Run Configuration의 Parameters에 입력
인자 없음 또는 --prepare
  오프라인 대상 준비와 개수 검증만 수행. DGT 조회·카카오·컴퓨터 종료를 실행하지 않습니다.
--run --limit 20
  실제로 새 번호 최대 20개를 조회하고 결과를 저장합니다. 이후 전체 실행 시 재사용합니다.
--run
  준비된 대상의 남은 번호부터 실제 조회합니다. 완료·3회 실패 번호는 다시 조회하지 않습니다.
--export-only
  새 요청 없이 이 작업의 체크포인트를 CSV로 다시 저장합니다.
--no-kakao
  해당 실행에서 카카오 보고를 보내지 않습니다. 실제 조회의 기본은 카카오 보고 켜짐입니다.
--job-name 새작업이름
  다른 대상 준비/체크포인트를 별도 폴더에 보관할 때 사용합니다.

작업 폴더: PJ_DATA/조회기록/DGT_자부두환적
결과 폴더: PJ_DATA/조회결과/DGT_자부두환적
현재 작업 폴더의 stop_requested.json을 만들거나 콘솔에서 Ctrl+C를 누르면 저장 후 중단합니다.
재개 전 stop_requested.json을 직접 제거한 뒤 --run을 실행합니다.
중복 실행은 Windows 파일 잠금으로 차단합니다.
입력이 변경되면 기존 작업을 덮어쓰지 않고 다른 job-name을 요구합니다.

3. 수집 방법
공식 화면: https://www.dgtbusan.com/DGT/esvc/cntr/cntrInfo
번호 한 번의 기본 명세 요청으로 반환되는 방문 주기를 모두 저장·구분합니다.
기본 요청은 기존 코드와 같은 /DGT/container/containers를 사용합니다.
자부두 조건을 충족하는 회차에만 기존 코드 requests_for의 상세 요청을 수행합니다.
기본 명세의 모든 필드와 파손·통관·홀드·냉동·재조작·선박일정·작업예정·비용 응답을 보존합니다.
상세 요청은 순차 처리합니다. 번호 처리 후 0.7~1.5초 무작위 대기합니다.
인터넷 단절은 30~60초씩 대기하며 연결 복구 후 같은 번호를 재개합니다.
일반 오류는 번호당 총 3회까지 시도합니다. 성공한 기본/상세 항목은 재사용합니다.
단절 대기는 오류로 저장하거나 시도 횟수에서 차감하지 않습니다.
401/403으로 접근이 제한된 선택 상세는 공개 접근 제한으로 보존하며 우회하지 않습니다.
세션·인증 토큰은 요청에서만 사용하고 원문에 저장하지 않습니다.

4. 판정: DGT_SELF_TS.csv는 명세에 의한 자부두 조건 충족 회차
같은 방문 point에서 in.mode=S, out.mode=S여야 합니다.
양하·적하 모선항차가 모두 있고 모선 코드(앞 4자리)가 달라야 합니다.
Class는 TI/TX/TL, 상태는 Loaded, 취소되지 않은 회차여야 합니다.
차량번호가 함께 존재하면 충돌 검토 대상으로 남깁니다.
반입·반출 시각은 모두 2024-11-01 이상 2026-03-01 미만이어야 합니다.
반출은 반입보다 늦어야 하고 간격은 달력 3개월 이내(경계 포함)여야 합니다.
원본 환적 표시 행과 명세의 가장 가까운 시각 차이도 달력 3개월 이내여야 합니다.
동일 모선·시각 누락·취소·기간 불일치·Class 불확실 등은 검토.csv에 보존합니다.
선박 양방향이 아닌 회차는 비해당.csv에 보존합니다. 번호 전체가 비환적이라는 뜻은 아닙니다.
조회 자체가 3회 실패하면 ERROR.csv에 성공한 원문·항목과 함께 보존합니다.

중요한 해석 범위
원본 dgt.csv는 도로 반출입으로 수집됐으므로 원본 행 자체는 자부두 회차 증거가 아닙니다.
같은 번호의 다른 명세 회차에서 자부두 조건을 발견할 수 있습니다.
번호가 같고 3개월 이내여도 원본 도로 회차와 동일 회차라고 확정하지 않습니다.
결과는 이 번호 집합에서 확인한 명세 회차이며 DGT 전체 자부두 물동량이 아닙니다.
고유 번호 수와 방문 회차 수를 구분합니다. SELF와 OTHER에 같은 번호가 나올 수 있습니다.
명세반입반출간격_시간은 표시된 시각의 차이입니다. 실제 크레인 양하→적하 시간으로 단정하지 않습니다.
접안 예정시각을 개별 컨테이너 작업시각으로 대신 사용하지 않습니다.
홀드·냉동·비용 등 일부 상세는 조회시점의 번호 단위 응답일 수 있어 과거 회차 확정값이 아닙니다.

5. 저장과 설명
DGT_SELF_TS.csv: 위 조건 충족 명세와 상세 응답. 명세.*는 기본 원문, 상세.*는 상세 원문.
검토.csv: 기본 명세는 성공했지만 자부두 판정 조건이 부족하거나 기간이 맞지 않는 회차.
비해당.csv: 선박→선박이 아닌 회차의 기본 명세. 같은 번호의 다른 회차와 구분.
ERROR.csv: 최대 3회 후 기본 또는 상세 조회가 실패한 회차. 일반 검토와 구분.
목록/배열 필드는 JSON 문자열로 저장. 빈값과 접근 제한은 0 또는 없다고 해석하지 않습니다.
원문은 조회기록/raw/접두어/번호.json.gz에 기본/상세를 모두 보존합니다.
targets.sqlite3는 번호와 원본 환적 행 시각/행번호를 보존합니다.
progress.sqlite3는 번호별 상태 및 CSV용 회차 행을 같은 트랜잭션으로 저장합니다.
SQLite 분석은 mode=ro로 열고 immutable을 사용하지 않습니다.
CSV는 1,000개 번호 처리마다, 표본 종료·전체 완료·사용자 중단 때 갱신합니다.
실시간 체크포인트가 CSV보다 앞설 수 있습니다.
최종 저장 시 대상 번호 누락·혼입 및 체크포인트와 CSV 번호 일치를 검사합니다.
원본 행이나 기존 HJNC/BPT 행을 명세 결과에 합치지 않습니다.

6. 보고와 종료
실제 --run에서 시작, 첫 20개 실측 예상시간, 정각/30분, 완료·중단 보고를 카카오로 보냅니다.
초기 예상은 첫 20개 실측 후 제공하며 인터넷 대기/추가 방문 회차에 따라 변동합니다.
기존 등록 앱을 재사용하므로 카카오 버튼은 BPT 링크일 수 있고 본문은 DGT 자부두 전용입니다.
카카오 실패는 kakao_report_status.json에 남기고 조회 결과를 오류로 바꾸지 않습니다.
이 신규 코드는 완료 후에도 컴퓨터 전원을 끄지 않습니다.
전체 크롤링은 --run을 사용자가 실행하거나 별도로 시작 지시한 뒤 진행합니다.
